# Trimming et commutateurs de fonctionnalité

Un compilateur AOT (ahead-of-time) voit le programme entier avant qu'il ne s'exécute. En partant du point d'entrée, il suit chaque appel, chaque type construit et chaque méthode virtuelle susceptible d'être atteinte, compile ce qu'il atteint et laisse tout le reste hors de l'image. C'est le trimming. Il permet de garder petit un noyau construit à partir de grandes bibliothèques, et il implique aussi qu'un code doit être atteignable pour exister : une classe que rien ne référence n'est pas dans l'image, quel que soit l'assembly dont elle provient.

Un commutateur de fonctionnalité décide de l'atteignabilité au moment du build. C'est un paramètre nommé, fixé à la compilation du programme et lu à travers une propriété que le compilateur connaît. Le compilateur remplace chaque lecture de cette propriété par la valeur du commutateur : une branche gardée par un commutateur désactivé teste donc une constante `false`, ne peut jamais s'exécuter et est supprimée, avec tout ce que seule cette branche atteignait. Désactiver un sous-système de cette façon retire son code de l'image au lieu de le sauter à l'exécution.

Le piège est une référence hors de la garde. Le trimming supprime ce qui est inatteignable, pas ce qui est gardé : si un code qui reste dans l'image référence un type, ce type reste aussi, même avec son commutateur désactivé. Un commutateur est aussi un paramètre de build, si bien qu'un noyau compilé avec une fonctionnalité désactivée ne peut pas l'activer à l'exécution ; le code n'y est pas.

Dans Cosmos, chaque propriété `CosmosEnable*` du `.csproj` d'un noyau devient une `RuntimeHostConfigurationOption` marquée `Trim="true"`, qui parvient à ILC, le compilateur NativeAOT ([Cosmos.Build.Ilc](../../dev/build/ilc-build.md)), sous la forme d'un argument `--feature:`. Les propriétés que remplace ILC se trouvent dans `CosmosFeatures` de Core, marquées `[FeatureSwitchDefinition]`, et `KernelFeatures` dans `Cosmos.Kernel.System` est la vue publique que lit un noyau. Certains commutateurs en désactivent d'autres : avec `CosmosEnableInterrupts` désactivé, `Sdk.targets` désactive aussi les commutateurs du minuteur, du clavier, de la souris, du réseau, du stockage, de l'ordonnanceur et de PCI, et avec `CosmosEnableScheduler` désactivé, le commutateur du thread du finaliseur (`CosmosEnableFinalizerThread`). Le manifeste des pilotes utilise les commutateurs comme gardes : un pilote déclaré `[Driver(Feature = DriverFeature.Network)]` est enregistré à l'intérieur de `if (KernelFeatures.Network)`, et comme rien d'autre ne construit un pilote fourni, un noyau compilé avec `CosmosEnableNetwork` désactivé n'embarque aucun pilote réseau. Voir [L'attribut et le manifeste](../drivers.md#the-attribute-and-the-manifest) et [Gardes de fonctionnalité](../../dev/build/driver-manifest.md#feature-guards).
