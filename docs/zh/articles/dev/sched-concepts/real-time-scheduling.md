# 实时调度

实时系统只有在其工作按时完成时才是正确的。这些工作通常被描述为一组任务，每个任务在每个周期释放一个作业（job），并带有最坏情况执行时间和截止时间，截止时间通常就是周期的结束。在硬实时中，错过截止时间就是故障，例如电机控制器；在软实时中，错过截止时间会降低结果的质量，例如出现爆音的音频。实时调度器要预先回答的问题是可调度性：给定这些任务，每个截止时间是否都能满足？

有两种经典策略在单个 CPU 上回答这个问题。速率单调（Rate Monotonic）根据每个任务的周期为其分配固定优先级，周期越短，优先级越高；对于这类任务，它是最优的固定优先级分配方式。当 n 个任务的总利用率（即每个任务的执行时间与其周期之比的总和）保持在 `n(2^(1/n) - 1)` 以下时，这组任务保证可调度，这个界限随着 n 的增大而下降并趋近于约 69%。最早截止时间优先（EDF）总是运行截止时间最近的就绪作业，这种优先级随每次释放而变化，并且在利用率达到 100% 之前都能满足所有截止时间。两者失效的方式也不同：在过载时，速率单调首先错过其最低优先级任务的截止时间，而过载的 EDF 可能会在所有任务上连锁地错过截止时间。准入控制（admission control）在任务创建时就拒绝会使利用率超过界限的任务，从而使系统保持在界限以下，而不是任其在之后造成截止时间错过。

陷阱在于分析假定有界的一切。只有当每项开销都已知时，这些保证才成立：调度器自身的决策时间、中断延迟、低优先级线程持有某个任务所需的锁的时间，以及释放作业的定时器的粒度。耗时与线程数量成线性关系的线程选择、没有[优先级继承](priority-inversion.md)的锁，或者比最短截止时间更粗的[节拍](scheduler-tick.md)，都会在每个任务都没有超出自身预算的情况下破坏这一保证。

在 Cosmos 中，默认没有任何部分是实时的：Stride 策略按份额而不是按截止时间划分时间。策略可以基于 `IScheduler` 实现速率单调或 EDF，并且必须通过它自己的入口点提供自己的准入控制，因为没有任何钩子能拒绝线程，内核中也没有任何机制限制利用率。内核一侧同样缺少一些部分。节拍以固定周期运行，从启动起即为 10 ms，因此截止时间最多只能精确到最近的节拍，而且没有任何通道能让策略为其最近的截止时间设定下一次定时器中断。`OnTick` 和 `PickNext` 会增加中断延迟，因此必须限制它们的开销，而且 `Mutex` 没有优先级继承。参见[实时说明](../../user/scheduler-plugging.md#real-time-notes)。
