# ABA 问题

无锁代码通过比较并交换（compare-and-swap，`Interlocked.CompareExchange`）来更新共享状态：读取值，计算新值，只有当该值仍是先前读到的值时才把新值写回。这一检查有个盲点：如果另一个线程在此期间把值从 A 改成 B 又改回 A，比较仍会成功，尽管它所描述的状态已经不复存在。这就是 ABA 问题。对于指针和指向可复用槽的索引而言，“值相同”并不意味着“含义相同”。

标准的解决办法是版本标签：在值旁边打包一个计数器，每次更新都将其递增，这样被复用的值在比较时就不再相等。

在 OrionGC 中，句柄存储区就采用了这一方案：每个句柄段把自己的空闲链表头、存活计数和一个版本标签打包进一个 64 位字，用 `CompareExchange` 更新，因此即使某个槽在两次读取之间被释放又重新分配，也不会被误认为空闲链表没有变化。参见[句柄存储区](../garbage-collector.md#handle-store)。
