# 指针碰撞分配

指针碰撞分配（bump allocation）通过推进一个指针来分出内存：分配器在一块空闲区域中维护一个游标，对每次请求返回当前游标，再把游标向前推进所请求的大小。一次分配只需一次比较和一次加法，相继分配的对象在内存中彼此相邻，这有利于缓存局部性。

它的局限在于只适用于从未使用过的空间。一旦区域中间有对象被释放，这些空洞就不再位于游标后方，因此必须通过空闲链表回收再利用。

在 OrionGC 中，每个段都有一个用于新空间的 `Bump` 游标，线程在各自的 [TLAB](tlab.md) 内独自进行指针碰撞，清除留下的空洞则进入按大小类别划分的空闲链表。参见[段](../garbage-collector.md#segments)和[空闲链表](../garbage-collector.md#free-lists)。
