# USB（通用串行总线）

USB 以树形结构连接设备，树的根是主机控制器。设备通过描述符描述自身：先是厂商 ID 和产品 ID，然后是由一个或多个接口组成的配置。接口是设备的一项功能，它的类别、子类别和协议说明它是什么。接口通过端点（endpoint）通信，端点是单向通道，IN 方向通往主机，OUT 方向来自主机；此外，每个设备都有控制端点 0。每个端点都有一种传输类型：控制传输用于请求，批量传输用于没有时序保证的大量数据，中断传输用于延迟有上限的小型报告，等时传输用于音频等数据流。

中断这一传输类型的名称具有误导性。USB 设备没有通往 CPU 的中断线，也从不发起传输：每一次传输都由主机控制器调度。中断 IN 端点是控制器按其描述符要求的间隔轮询的端点，没有新数据的设备会回答它没有数据，整个过程都不需要 CPU。到达 CPU 的是控制器自己在传输完成时发出的中断，因此接收报告的代码可以运行在这个中断处理程序中，也就是运行在[中断上下文](interrupt-context.md)中。

集线器和枚举属于总线的主机一侧。集线器（hub）是带有下游端口的设备，控制器的根端口也起着集线器的作用。插入设备时，主机会复位它的端口，为它分配地址，读取它的描述符并选择一个配置，之后才把它的接口交给类驱动程序。

主机控制器是一个 PCI 功能，它的类别字节指明了它的编程接口，PC 上出现过四种。OHCI（类别 0x0C，子类别 0x03，接口 0x10）是许多芯片组（其中包括 AMD 和 NVIDIA 的芯片组）的 USB 1.1 主机接口：它根据自己在内存中遍历的端点描述符列表和传输描述符列表，驱动低速（1.5 Mb/s）和全速（12 Mb/s）设备。UHCI（接口 0x00）是 Intel 和 VIA 芯片组的 USB 1.1 主机，通过端口 I/O 编程，Cosmos 中没有它的驱动程序。EHCI（0x20）是 USB 2.0 主机，只驱动高速（480 Mb/s）设备，因此插在它某个端口上的全速或低速设备必须交给别处处理，芯片组用两种方式解决了这个问题。AMD 和 NVIDIA 为 EHCI 配备了与它共享端口的 OHCI 伴随功能（companion）：EHCI 通过端口所有者位把这样的端口交给伴随控制器，由伴随控制器把该设备当作自己的设备来枚举。后来的 Intel 芯片组在 EHCI 和它的端口之间放置了一个速率匹配集线器（rate matching hub），即焊接在主板上的高速集线器，于是慢速设备出现在该集线器后面，它的事务以分离事务（split transaction）的形式传送：一个 start-split 和一个 complete-split，发往集线器的事务转换器（transaction translator），由事务转换器在下游以设备的速度执行这次慢速事务。xHCI（0x30）是 USB 3 主机，一个控制器就能驱动所有速度，两种方案都不需要。

陷阱在于从节点路径推断插口。决定设备落在哪个控制器的总线上的是它插入的端口，而不是设备本身：在 AMD 主板上，插在 USB 2 插口里的全速键盘由 OHCI 伴随控制器枚举，而不是由它所插入的 EHCI 枚举；同一个键盘在这块主板上位于根端口上，在 Intel 主板上则位于速率匹配集线器后面，因此一台机器上的 `usb:2-1:0` 和另一台机器上的 `usb:1-1.3:0` 可能是插在同类插口中的同一个设备。类驱动程序完全看不到这些，这就是枚举由主机控制器驱动程序和集线器驱动程序负责的原因。内核启动时，控制器也可能仍由固件驱动，用来模拟 PS/2 键盘（[固件交接](firmware-handoff.md)），而且每种控制器都会把设备的连接和断开作为[热插拔](hot-plug.md)事件上报。

键盘和鼠标属于 HID（human interface device，人机接口设备）类，这类设备通常在报告描述符中描述自己的报告格式，由主机解析，而这超出了人们对 PC 固件的期望。启动协议是格式固定的替代方案：子类别为 1、协议为 1（键盘）或 2（鼠标）的接口，在 SET_PROTOCOL 请求选中该协议后，会发送 8 字节的键盘报告（修饰键、一个保留字节、最多六个按下的键），或者由按钮状态以及随后的 X 和 Y 位移组成的鼠标报告。

在驱动工具包中，一个 USB 节点就是一个接口，通过 `UsbAccess` 访问，它的 `OpenInterruptPipe` 把每个报告交给一个 `UsbReportHandler`。当控制器以中断通知传输完成时（xHCI 上是 MSI-X 消息，EHCI 和 OHCI 上是该功能的传统中断线），这个处理程序运行在中断上下文中；当控制器被轮询时，它运行在线程上下文中，因此无论哪种情况，它都要遵守中断处理程序的规则。`XhciDriver`、`EhciDriver`、`OhciDriver` 和 `UsbHubDriver` 把每个新设备交给工具包的枚举流程，类驱动程序永远看不到这一过程。参见 [USB 访问对象](../drivers.md#the-usb-access-object)、[主机控制器契约](../drivers.md#the-host-controller-contract)和 [USB 类驱动程序](../drivers.md#the-usb-class-drivers)。
