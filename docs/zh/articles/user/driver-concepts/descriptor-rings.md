# 描述符环

一个要搬运数据包流或磁盘块流的设备，不能每次只交给它一个缓冲区：那样驱动程序就得等待每一次传输，而一阵突发到达的帧也会无处落脚。描述符环（descriptor ring）同时解决了这两个问题：它是位于 [DMA](dma.md) 内存中的一个固定数组，由一些小记录（即描述符）组成，驱动程序和设备都会读写它。每个描述符保存一个数据缓冲区的[物理地址](physical-addresses.md)和长度，外加一些状态位；这个数组被当作循环队列使用，用到最后一项之后会绕回第一项。

任何时刻，每个描述符都只属于其中一方。驱动程序填写自己拥有的描述符并把它们交出去；设备按顺序处理属于自己的描述符，处理完一个就交还一个。有两种约定可以标记这条分界线，二者常常结合使用。在第一种约定中，尾索引是驱动程序放入下一个描述符的位置，头索引是设备取走下一个描述符的位置，从头到尾之间的各项属于设备。在第二种约定中，每个描述符带有一个所有权位或“完成”位，由交出该描述符的一方翻转。网卡维护两个环：一个接收环，由驱动程序放入空缓冲区；一个发送环，由驱动程序填入要发出的帧。

驱动程序通过写一个寄存器来告诉设备有新的描述符已就绪，这个寄存器就是门铃，通常就是尾寄存器本身。反方向则不需要寄存器：驱动程序根据设备写入描述符的状态得知哪些描述符已经完成，因此一次中断或一次轮询就能回收一整批描述符。

陷阱在于顺序。设备一看到门铃或所有权位，就可能读取描述符，因此描述符的内容必须先到达内存；驱动程序也必须先读取“完成”位，再读取受它保护的缓冲区长度或数据。[内存屏障](barriers.md)同时保证这两点。

在驱动工具包中，环位于由 `binding.AllocateDma` 分配的 `DmaBuffer` 中：交出描述符之前调用 `DmaBuffer.WriteBarrier()`，读取“完成”位之后调用 `DmaBuffer.ReadBarrier()`，门铃则通过 `RegisterWindow` 写入，它的写入自带屏障。Virtio 设备使用工具包自己的环，即 `Virtqueue`（[virtio](virtio.md)）；参见 [DMA 内存](../drivers.md#dma-memory)和[队列](../drivers.md#queues)。
