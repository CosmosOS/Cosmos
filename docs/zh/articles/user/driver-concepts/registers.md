# MMIO（内存映射 I/O）与端口 I/O

设备以寄存器的形式暴露它的控制接口：寄存器是一些很小的位置，驱动程序读取它们来获知设备的状态，写入它们来向设备下达命令。使用内存映射 I/O（MMIO）时，设备响应一段[物理地址](physical-addresses.md)，这段地址映射之后，普通的加载和存储指令就能访问到它。x86 还有一个独立的端口空间，共 65536 个地址，只能通过 `in` 和 `out` 指令访问，每次最多 32 位；[PS/2 控制器](ps2.md)等较老的设备至今仍位于其中。ARM64 没有端口空间。

寄存器不是内存。读取可能带有副作用，例如清除某个中断原因，或者从 FIFO 中取走一个字节；写入则可能启动一条命令，因此把一个值写两次，就可能把命令执行两次。每次访问都必须恰好发生一次，按程序顺序进行，并使用设备文档规定的宽度：把一个 32 位寄存器按四个字节读取，就是四次不同的访问；而且许多设备在宽度错误或访问未按其宽度对齐时会出现异常行为。

映射决定了 CPU 如何缓存这些地址，以页为单位。寄存器需要不可缓存的设备内存，在这种内存上，每次访问都按顺序到达设备，也不会有任何推测性读取。帧缓冲区是位于设备上的普通内存，在不可缓存的映射下绘制会很慢，因此它被映射为写合并（write-combining）：存储操作被合并成突发传输，并放弃彼此之间的顺序。普通的可缓存内存适用于一致性设备与 CPU 共享的 RAM。被缓存的寄存器会悄无声息地出错：返回过时的值，并把写入滞留在缓存中。

在驱动工具包中，`binding.MapRegisters` 返回一个 `RegisterWindow`，它的 `Read8` 到 `Read64` 以及 `Write8` 到 `Write64` 每次调用都执行一次相应宽度的访问，并检查边界，在内存窗口上还检查对齐；在 x64 端口范围上，它们使用 `in` 和 `out`，接受任意偏移量，而 64 位的方法会抛出异常。`binding.MapRegion` 接受一个 `RegionCaching`，取值为 `Device`、`WriteCombining` 或 `Normal`，不过目前只有 x64 会应用 `WriteCombining`，而且只应用于区域完整覆盖的 2 MiB 块，其他所有内存窗口都按 `Device` 映射。参见[寄存器窗口](../drivers.md#register-windows)和[大块内存区域](../drivers.md#bulk-regions)。
