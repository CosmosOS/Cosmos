# 总线与枚举

总线把设备连接到处理器，而枚举是软件查明总线上有哪些设备的方式。PCI 和 USB 可以被枚举，因为每个设备都在一个可预测的位置应答，并给出关于自身的标准描述：软件在每个 PCI 地址读取厂商 ID，空插槽读出的值所有位均为 1（[PCI](pci.md)），软件还会向每个新的 [USB](usb.md) 设备索取它的描述符。

其他设备没有提供这样一个可供询问的位置。PC 的 [PS/2](ps2.md) 控制器位于固定的 I/O 端口，ARM 机器的设备位于固定的内存地址，而每次 PCI 扫描的起点，即 PCI 主机桥，也属于这一类。读取一个无人应答的地址可能引发异常，而能应答的设备也没有标准的方式说明自己是什么，因此必须把这些平台设备描述给内核。在 PC 和 ARM 服务器上，由固件的 ACPI 表描述它们。在许多 ARM 开发板上，则由设备树描述：设备树是引导加载程序交出的一种结构，其节点列出每个设备的寄存器、中断和兼容字符串（compatible），兼容字符串就是该设备所遵循的编程模型的名称。布局固定的机器，例如 QEMU 的 virt 机器，也可以由内核中的一张表来描述。

这两类设备组合成一棵树。描述给出根节点，而作为总线控制器的根节点，其驱动程序会枚举自己的总线，并把发现的设备作为子节点发布，供其他驱动程序绑定：PCI 主机产生 PCI 功能，其中一个功能可能是 USB 控制器，它又产生 USB 设备。

陷阱在于没有任何东西能证实一份描述。描述遗漏的设备是不可见的，而描述列出但实际不存在的设备，会让驱动程序去探测空地址。

在驱动工具包中，平台节点在启动时由机器描述发布：在 x64 上是固定的 PC 布局，包括 8042 控制器（`pnp0303`）和 PCI 主机（`pci-host-legacy`）；在 ARM64 上是来自 ACPI 或设备树的 PCI 主机，以及每个已占用的 `virtio,mmio` 插槽，后者来自设备树或 virt 机器的固定布局（[平台节点](../drivers.md#platform-nodes)）。驱动程序用 `PlatformMatch.Compatible` 匹配它们，总线驱动程序用 `binding.PublishChild` 添加子节点，因此每个节点的 `Parent` 和 `Children` 构成了这棵树（[发布子节点](../drivers.md#publishing-child-nodes)，[总线](../drivers.md#buses)）。
