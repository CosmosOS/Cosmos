# 中断投递

设备通过发出中断请求（IRQ）来请求 CPU 的关注，该请求经由中断控制器传递：在 x64 上是 I/O APIC 和本地 APIC，在 ARM64 上是 GIC。控制器为各个中断源编号，可以单独屏蔽每一个中断源，并把一个请求转换成内核据以分派的编号。中断处理程序运行完毕后，内核发出中断结束（end of interrupt）信号，以便控制器投递下一个中断。

中断结束通知的是控制器，而不是设备。设备把待处理的中断原因保存在一个状态寄存器中，只有它的驱动程序知道如何清除。电平触发的中断线在有待处理原因期间一直保持有效，因此一个没有清除该原因的处理程序会立即再次运行，无休无止。在边沿触发的中断线上，控制器只能看到电平跳变，因此一个未被清除的待处理原因可能再也不会产生新的边沿，设备就此沉默。无论哪种情况，处理程序都要先确认设备的中断。屏蔽中断源是另一种手段，用于只有线程才能清除的中断原因。

经典的 PCI 功能通过传统引脚（INTx）发出中断信号，这是一根电平触发的连线，其路由因主板而异，并且可能被多个设备共享，因此挂在它上面的每个处理程序都要检查中断是不是自己的设备发出的。MSI 和 MSI-X 用一次内存写入取代了这根连线：设备把一个值写入一个地址，两者都由内核选定，控制器再把这次写入转换成中断。消息从不共享，不需要主板路由，而且一个设备可以为每个队列各配一个消息。MSI-X 把它的消息表（每个表项带一个屏蔽位）放在设备的某个 [BAR](pci.md) 中。

在驱动工具包中，PCI 节点的传统中断线只在 x64 上路由，仅限第 3 到第 15 号中断线，从不共享，并被编程为边沿触发，QEMU 能够投递这种中断，但真实芯片组未必能；它的消息只支持 MSI-X，最多 32 个，在 ARM64 上需要 GICv3 中断转换服务（ITS），并且连接其中一个消息就会关闭该中断线。`InterruptHandle.Mask()` 和 `Unmask()` 停止和恢复单个中断源：对中断线是在控制器上操作，对消息则是在表中操作。参见[中断](../drivers.md#interrupts)、[传统中断线](../drivers.md#the-legacy-line)和[消息中断](../drivers.md#message-interrupts)。
